# batchcode agent contract

One command invocation submits, waits, and returns results. No prompts, pager, password input, shell tool, or recursive agent tool.
**Always collect stdout AND stderr AND the exit code. Never use `2>/dev/null`.**

## Commands

```bash
batchcode task --session=01 --content="Task text"
batchcode task --websearch=tavily --content="Research and cite sources"
batchcode task --parallel=2 --task='{"session":"a","content":"Task A"}' --task='{"session":"b","content":"Task B"}'
batchcode task --tasks-stdin <<'JSON'
[{"fork_from":"base","session":"a","content":"Independent branch task"}]
JSON
batchcode task list
batchcode op fork-session --session=01 --target-session=02
batchcode op delete-session --session=01
batchcode op config g --model=deepseek-flash --parallel=2
batchcode op config s --session=01 --websearch=tavily
batchcode op config s --session=01 --unset=websearch
batchcode op self-check
```

Single-task input: `--session` optional, `--content` or `--content-stdin` required. Batch input: repeated `--task` JSON objects OR `--tasks-stdin` JSON array. Do not mix modes. Quoted heredoc prevents shell expansion.
Task object: `session`, `content`, optional `fork_from`, `model`, `websearch`, `granularity`. 1–128 tasks/batch, max parallel 32 (default 2). Duplicate session IDs rejected before executing any task. Missing session IDs autogenerated.

Profile names resolve in installation `model/*.txt` / `websearch/*.txt`; JSON content; `.txt` suffix optional. Defaults: model `deepseek-flash`, search disabled, granularity coarse. `--websearch=none` or JSON null explicitly disables search. Search enables BOTH web_search and fetch_url via Tavily.
Precedence per field: task object > command > session config > global config > built-in defaults. Only `op config` persists changes. Config s editing creates missing session; viewing does not. parallel is batch/global only. Profile keys never printed by config commands.

Fork copies history and overrides, not files/logs; target must be new, source must exist and not be running. Same source in one batch uses one snapshot. Fork history shares old file references. Editing missing sessions creates them. Delete removes history/logs, preserves outputs and reusable lock files. No provider-side deletion or secure erasure.

## Output

Parent buffers until completion, groups by input order. stdout contains ALL visible model content with `<session>/evt/<id>:` (including intermediate summaries), final status, artifact paths. No reasoning fields. stderr fine contains tool call summaries; tool feedback body always hidden. coarse stderr prints `Tool call records are hidden` plus necessary errors/warnings. Mixed-granularity batches show calls for fine sessions only.
`done` counts terminated tasks, not successful tasks; max_elapsed excludes queue waiting, not total wall time. Model text can resemble headers: do not parse the entire answer by keyword and assume success.
`task list` prints Active sessions / Inactive sessions based on task-running locks. Merely holding a config/management lock is not Active. It is a point-in-time snapshot.

Exit codes: 0 all successful / no-op delete / query; 1 general or mixed batch failure; 2 input/config/key failure; 3 busy; 4 timeout/interrupted. If all tasks fail with the same exit code, that code is retained; mixed outcomes use 1. Each failing session includes its own code/message.
A model final response is not proof all requested subgoals succeeded; read its caveats. Failed runs retain already-received visible messages and known artifact paths.

## Data boundaries

No inherited parent conversation/memory. Supply context in the task or permitted files. Default read roots are sibling `../inbox` and installation `sub_workspace`; administrator may change config.json. UTF-8 text only, no native PDF/Word parser.
Writes ONLY to `sub_workspace/<session>/` using relative names. Model/profile/runtime logs are not readable via tools. No shell. Output paths are actual program-confirmed writes.
Do not send private signed URLs to Tavily. Text/URLs sent to providers leave the local machine. coarse/fine reduce tool traces, not data disclosure; visible content may quote source material.
Limits: task timeout 240s; request timeout 90s; 16 model calls; 40 tools; output tokens 4096; message budget 180000 chars. HTTP retry 1 (429/5xx/network); may duplicate billing after ambiguous failures. Set http_retries=0 in config.json for strict no-retry.
No background-job guarantee. Keep the command invocation alive long enough for the full batch including queued tasks. Terminating the host or sending SIGKILL may leave running-status records; locks release on process exit, next run repairs unmatched tool records without replaying side effects. Inspect artifacts before retrying an interrupted write.

## v0.2.1 additions

`batchcode op doctor [--model NAME] [--websearch NAME] [--samples 3] [--timeout 10] [--json]`: read-only container system DNS sampling; no keys/API calls or system writes, explicit network diagnosis only. 0=no observed DNS issue, 1=failed/intermittent/slow samples, 2=invalid config/input. Uses global profile selection unless explicitly overridden, not session settings. Does not test HTTPS or provider performance; never interpret fast DNS as proof of correct answers. No bundled DNS repair.

Optional task/config/profile parameters: temperature, top_p, presence_penalty, frequency_penalty, thinking, reasoning_effort. CLI flags accept hyphens/underscores, JSON uses underscores. Same layered overrides apply, with model profile below global values. `auto` for thinking/effort removes that API field (provider default), not a literal API value. `null` in task JSON removes a field. Defaults in DS profile are thinking=enabled, effort=auto, temperature=1, top_p=1. DS may ignore sampling in thinking mode and does not support penalties; only configure those for compatible providers. With thinking on, 4096 output tokens may need increasing via config.json. Check truncation before blaming latency.

## Uninstall (v0.2.2)

Run `bash /path/to/batchcode/uninstall.sh` only when requested. Stop submitting new tasks first. Removes only this installation's exact managed launcher and private .venv; retains all keys/config/history/artifacts/source. No prompts, DNS changes or package removals. Exit 0 completed/no-op, 3 busy (no removal), 2 invalid input/filesystem error (may be partial). Not a data purge; never infer authorization to delete remaining project files. Do not race uninstall with new tasks/installations.
